# herdr-bottombar

A herdr plugin: a vertical layout for portrait monitors, swapped with herdr's
standard one by a single action. User-facing behaviour is in `README.md`; this
file is how it works and how to check a change.

## Environment

**Build.** none — Python 3.9 standard library, run by the system
`/usr/bin/python3` with `-B` so no `__pycache__` lands in a checkout
**Typecheck.** none
**Lint.** none
**Tests.** none; check with `/usr/bin/python3 -B -m py_compile herdr/*.py`,
then drive the plugin on a throwaway herdr server (below)
**Runtime.** a herdr 0.9 server, which runs every command from the plugin root

## Layout

- `herdr-plugin.toml` — actions `layout`, `minimize` and `navigate`, the `bar`
  pane, and `manage.py sync` on startup, `tab.created` and `tab.focused`.
- `herdr/manage.py` — the config swap and keeping one bar per tab.
- `herdr/panel.py` — the bar itself, a full-screen TUI over the socket API.
- `herdr/status.py` — the one line the tab bar shows while the bar is folded.
- `herdr/herdr_api.py` — socket client, plugin paths, state flags, split math.
- `herdr/gitinfo.py` — branch and ahead/behind for a directory, cached.

## Checking a change on a throwaway server

Never test against the live session: plugin registration is per `HOME`, so a
`herdr plugin link` under the real one runs the plugin's hooks in the live
session at once.

1. Unset every `HERDR_*` variable — inside a herdr pane they point the CLI at
   the live server — and give the server a short `HOME`; a long one overflows
   the Unix socket path. A wrapper keeps that out of every command:
   `env -u HERDR_SOCKET_PATH -u HERDR_ENV -u HERDR_PANE_ID -u HERDR_TAB_ID -u HERDR_WORKSPACE_ID -u HERDR_BIN_PATH HOME=/private/tmp/claude-501/hb herdr "$@"`.
2. Start it with `<wrapper> server` in the background, `<wrapper> plugin link`
   this checkout, create workspaces, and drive the actions with
   `<wrapper> plugin action invoke scheron.bottombar.layout`.
3. Without a client the server lays tabs out for a headless 120x40 screen. To
   see real chrome — dividers, the tab bar, the native sidebar — run the
   wrapper as a client inside a tab of the live session and read that tab with
   `herdr pane read <pane> --source visible --format ansi`; keys reach it
   through `herdr pane send-keys <pane> ctrl+g` and then the key.
4. Fake agents with `<wrapper> pane report-agent --source test --agent claude
   --state working <pane>`.
5. Stop the server and delete the `HOME` afterwards.

## What herdr allows, and what that forced

- **The native sidebar cannot be driven by a plugin.** No API shows or hides
  it, and a key bound to both `toggle_sidebar` and a plugin action keeps only
  the built-in (`herdr config check` says so). A reload can change its widths,
  though, and width 0 hides it whether expanded or collapsed (with
  `sidebar_collapsed_mode = "hidden"`). So a layout switch is a config switch:
  `manage.py` writes a generated copy of the user's config — first line
  `# Generated by the bottombar plugin from <base> for the vertical layout;`,
  which is also how it finds its way back — and reloads. A symlinked config is
  relinked to `<base>`; a regular file waits as `config.toml.bottombar-base`.
  The user's `toggle_sidebar` key is taken over by `minimize` in the copy.
- **Navigate mode draws only in the sidebar.** The cursor `workspace_picker`
  moves with the arrows lives in the client, out of reach of the API, and is
  painted only into the sidebar, so at width 0 it moves unseen. The copy hands
  that key to `navigate`, which focuses the tab's bar with `plugin.pane.focus`.
  The bar starts on the current space whenever it gains focus, noticed on its
  next refresh or its first key, whichever comes first — not from focus
  reports: `pane.focus` sends none, and `plugin.pane.focus` reports only to the
  pane losing focus.
- **Focus up from a full-width bar lands on the leftmost pane.** So the bar
  remembers the pane its tab focused last and hands focus back to that one with
  `pane.focus`, falling back to the pane above when it has gone.
- **No pane can be under 10% of its tab.** `layout.set_split_ratio`,
  `pane.resize` and the mouse all stop at 0.1–0.9. Folding therefore closes
  the bars and puts a `command` entry in `tab_bar_right`; herdr strips ANSI
  styling from those, so the folded line has no colours.
- **Plugin panes take sizes only as popups.** `plugin.pane.open` rejects
  `height` for a split, so a bar opens at half its target and is sized with
  `layout.set_split_ratio`. The split is found by walking `layout.export`;
  `path` is a list of booleans, `true` meaning the second child.
- **A ratio set without a client is a ratio of 40 rows.** The startup hook runs
  before anyone attaches, so each bar re-fits itself whenever its rect changes,
  measuring its own pty to learn how many rows the divider costs.
- **Bars carry no label.** A label draws into the divider above the bar, and
  even a zero-width one leaves a gap. A live bar is known by its `panel.py`
  foreground process. A restore brings a bar back as a plain shell in the
  plugin root, which `sync` recognises by the pane ids it saved in `bars.json`
  in the state dir — pane ids survive a restore, terminal ids do not.
- **Tab titlers pick the newest pane.** herdr.auto-title names an unfocused tab
  without a working agent after the pane whose `revision` moved last, and a new
  bar is newest. Two seconds after starting, the bar reports a short-lived
  metadata token on its neighbours, which advances their revision.
- **Agent status events are per pane.** `pane.agent_status_changed` needs a
  `pane_id`, so the bar subscribes to lifecycle events and also polls
  `session.snapshot` every 1.5 s while its tab is shown.
- **A bar outliving its tab's last pane would keep the tab open.** It exits
  once its tab's `pane_count` is 1.
